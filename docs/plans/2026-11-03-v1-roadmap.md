# Tachylite v1 roadmap

**Spec:** `docs/superpowers/specs/2026-11-03-tachylite-design.md`, summarised as user stories in #14. Read it first; this file only orders the work.

v1 ships in ten slices. Each slice is one GitHub issue under the `v1` milestone, one branch and one or more PRs. Each one ends with working software and its budgets green. A slice gets its detailed plan in `docs/plans/` when it starts, so it can build on what the slices before it learned. Only slice 1 has a detailed plan so far.

The order follows one rule: prove the riskiest claim first. That claim is that a save reaches an open page in about 100 ms, so slice 2 builds that path end to end, and breadth comes after it.

| # | Issue | Slice | Done when | Budgets it brings under test |
|---|---|---|---|---|
| 1 | #3 | Skeleton | `tachylite build <vault> <out>` renders every note to plain HTML and copies html pages and assets. It obeys the publish list and the default exclusions. The gate, CI, the musl builds, the fixture vault and the budget vault all exist. | Cold full build; release binary |
| 2 | #4 | Live path | `tachylite serve <vault> <out>` serves the output on `127.0.0.1`. A save re-renders the note and pushes it over SSE, and the open page swaps in the new HTML. ## Decisions still open

- **The index page namespace (slice 7).** `/today`, `/recent` and `/tasks` collide with notes named `today.md`, `recent.md` or `tasks.md` at the vault root. The fix is to put index pages under a prefix no vault path can take, or to let the note win and log the clash. It must be decided before slice 7.
- **Search engine (slice 9).** Decided by measurement, as the spec says.

## Output layout

Slice 1 fixes this. Later slices add to it but never move it.

- `out/.tachylite-output`: a marker file. Tachylite clears or writes only a directory that is empty or carries this marker.
- `out/pages/<vault path without .md>.html`: note pages.
- `out/files/<vault path>`: html pages and assets, byte for byte.

The server percent-decodes the URL path to `P`. It serves `pages/P.html` if that exists, else `files/P`. So `/maps/route` serves the note `maps/route.md`, and `/maps/route.html` serves the html page `maps/route.html`. They never share a file.
